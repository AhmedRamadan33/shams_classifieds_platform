# Deploying Shams (شمس)

A checklist for putting the classifieds platform on a Linux server (Ubuntu/Debian instructions).
Everything below assumes the code is checked out in `/var/www/shams` and the site runs on `https://your-domain.com`.

## 1. Server requirements

| Component | Requirement |
|---|---|
| PHP | 8.3+ with `pdo_mysql`, `mbstring`, `intl`, `gd` (**with WebP support**), `exif`, `fileinfo`, `zip`, `xml`, `curl`, `bcmath`, `opcache` |
| MySQL | **8.0+** (InnoDB, `utf8mb4`). FULLTEXT search relies on InnoDB |
| Web server | Nginx + PHP-FPM (Apache also works with `public/.htaccess`) |
| Node | 20+ (only to build assets; not needed at runtime) |
| Composer | 2.x |
| Process manager | Supervisor (queue worker) |
| Cron | one entry for the scheduler |

`mysqldump` must be installed for the database backups (`mysql-client` package).

Check GD/WebP: `php -r "var_dump(gd_info()['WebP Support']);"` must print `true`.

## 2. First deploy

```bash
cd /var/www/shams
git clone <repository> .
cp .env.example .env            # then edit it: see the production checklist below
composer install --no-dev -o
npm ci && npm run build
php artisan key:generate
php artisan migrate --force --seed   # roles, admin user, governorates/cities, categories, static pages
php artisan storage:link
php artisan optimize
```

The seeders are idempotent, so `--seed` is safe on every deploy. Static pages that already exist
(and were edited in the admin panel) are never overwritten.

Create the MySQL database and user first, with `utf8mb4` / `utf8mb4_unicode_ci`:

```sql
CREATE DATABASE shams CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'shams'@'localhost' IDENTIFIED BY '<strong password>';
GRANT ALL PRIVILEGES ON shams.* TO 'shams'@'localhost';
```

> **InnoDB is mandatory.** Some hosts (and local WAMP installs) default to MyISAM. The app forces
> `engine = InnoDB` in `config/database.php`; verify with `SHOW TABLE STATUS` after migrating.

### Full-text search note

Search uses `MATCH ... AGAINST` on `listings.search_text`. InnoDB ignores tokens shorter than
`innodb_ft_min_token_size` (default 3); the app falls back to `LIKE` for shorter terms, so you do
not need to change that setting. `search_text` also stores each word without its definite article/glued
preposition (`App\Services\ArabicText::withSearchVariants`), so a search for «شقة» finds «الشقة» and
vice versa. If you ever change how `search_text` is built, run `php artisan listings:reindex` to
rebuild it for every existing listing (it only writes rows that actually changed).

```dotenv
CACHE_STORE=file                      # or redis
SESSION_DRIVER=database

MAIL_MAILER=smtp                      # backup failure alerts use it; "log" silently drops them

SMS_DRIVER=twilio                     # or vonage; "log" cannot deliver codes in production, see below
TWILIO_SID=...
TWILIO_TOKEN=...
TWILIO_FROM=...                       # or TWILIO_MESSAGING_SERVICE_SID

BACKUP_NOTIFICATION_EMAIL=ops@your-domain.com
CLASSIFIEDS_CONTACT_EMAIL=support@your-domain.com   # shown on the «اتصل بنا» page

CAPTCHA_DRIVER=turnstile              # recommended; see "CAPTCHA" below
TURNSTILE_SITE_KEY=...
TURNSTILE_SECRET_KEY=...

PAYMENT_DRIVER=paymob                 # "fake" settles instantly and must never be used in production
PAYMOB_API_KEY=...
PAYMOB_INTEGRATION_ID=...
PAYMOB_IFRAME_ID=...
PAYMOB_HMAC_SECRET=...

WHATSAPP_DRIVER=cloud                 # optional; "log" (default) sends no real WhatsApp messages
WHATSAPP_PHONE_NUMBER_ID=...
WHATSAPP_ACCESS_TOKEN=...
```

Then run `php artisan launch:check` (below) — it verifies every one of these before you go live.

Behind a load balancer or reverse proxy that terminates TLS, tell Laravel to trust it (otherwise
generated URLs, canonical links and the sitemap use `http://`): add
`$middleware->trustProxies(at: '*');` (or your proxy IPs) inside `withMiddleware()` in `bootstrap/app.php`.
`APP_URL` must match the public `https://` origin.

Redis is supported through `.env` only: `CACHE_STORE=redis`, `QUEUE_CONNECTION=redis`,
`SESSION_DRIVER=redis` plus the `REDIS_*` variables. No code changes are needed.

### SMS gateway (important)

`SMS_DRIVER=log` writes the one-time codes to `storage/logs/laravel.log`, which is fine for local
development but means **real users cannot receive codes**, so `launch:check` fails on it outside
`local`/`testing`. Two real providers are built in:

- **Twilio**: `SMS_DRIVER=twilio`, `TWILIO_SID`, `TWILIO_TOKEN`, and either `TWILIO_FROM` (a Twilio
  number) or `TWILIO_MESSAGING_SERVICE_SID`.
- **Vonage**: `SMS_DRIVER=vonage`, `VONAGE_KEY`, `VONAGE_SECRET`, `VONAGE_FROM` (an approved sender ID).

Either way, delivery failures never leave an unusable OTP behind: the code is deleted and the user
sees a friendly error and can retry immediately (`App\Services\OtpService`, `SmsDeliveryException`).
To add another provider, implement `App\Services\Sms\SmsGateway` and return it from
`AppServiceProvider::register()` for a new driver name.

### CAPTCHA

`CAPTCHA_DRIVER=null` (the default) disables the CAPTCHA — the honeypot field and rate limiters still
apply, which is enough for a low-traffic launch. For public exposure, set `CAPTCHA_DRIVER=turnstile`
and `TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY` (free, from the Cloudflare dashboard → Turnstile).
The widget then appears on registration and on the last step of the ad form
(`resources/views/components/captcha.blade.php`); `TURNSTILE_FAIL_OPEN=false` rejects requests instead
of letting them through if Cloudflare itself is unreachable (default: let them through). To add
another provider (reCAPTCHA, hCaptcha), implement `App\Services\Captcha\CaptchaVerifier` and register
it in `AppServiceProvider`; no controller needs to change.

### Featured-ad payments (Paymob)

`PAYMENT_DRIVER=fake` (the default) settles every "ميّز إعلانك" purchase instantly without charging
anything — fine for development and demos, but `launch:check` fails on it in production. To take real
payments:

1. Create a Paymob account, an "Online Card" integration, and an iframe; note the API key, the
   integration id and the iframe id.
2. Set `PAYMENT_DRIVER=paymob`, `PAYMOB_API_KEY`, `PAYMOB_INTEGRATION_ID`, `PAYMOB_IFRAME_ID`.
3. In the integration's settings, set the **HMAC secret** and put the same value in
   `PAYMOB_HMAC_SECRET` — every webhook is verified against it
   (`App\Services\Payments\PaymobWebhookVerifier`) before anything is trusted.
4. In the integration's settings, set the **webhook/callback URL** to
   `https://your-domain.com/payments/webhook/paymob` (server-to-server; this is what actually marks a
   payment paid and extends the listing's `featured_until`) and the **transaction redirection URL** to
   `https://your-domain.com/payments/return` (where the browser lands after paying; it only looks the
   payment up and shows its current status, it does not decide it).
5. Manage packages (name, days, price) from the admin panel → «باقات التمييز» («المدفوعات» group);
   payments are listed read-only under «المدفوعات». The same webhook/redirect URLs and credentials
   also cover store subscriptions (below) — it is the same Payment model and gateway for both.

### Seller stores & subscriptions

Any user can create a branded page at `/store/{slug}` (name, slug, bio) from `/store` — no
subscription needed for the page itself. Buying a plan at `/subscribe` (managed from the admin panel
→ «باقات الاشتراك») raises the buyer's daily listing limit to that plan's
`daily_listing_limit` (whichever is higher than `CLASSIFIEDS_DAILY_LISTING_LIMIT`, see
`App\Services\ListingLimits`) and shows a "متجر مميز" badge on their store page for as long as the
subscription's `expires_at` is in the future. Renewing the same plan, or switching to a different one,
while still active extends the existing subscription from its current expiry instead of starting a
new one. Subscriptions are listed read-only under «الاشتراكات»; stores under «المتاجر» (delete one
from there to remove an abusive page — sellers otherwise manage their own from `/store`).

### E-mail and WhatsApp notification copies

Every event (listing approved/rejected, expiring soon, a new chat message) always creates an in-app
notification. A user who adds an e-mail on their profile and turns on "أرسل لي نسخة بالبريد
الإلكتروني" also gets it by e-mail (`App\Notifications\Concerns\HasUserPreferredChannels`); a user who
turns on the WhatsApp toggle gets it on their verified phone number, through
`WHATSAPP_DRIVER=cloud` (Meta's WhatsApp Cloud API: create a Meta Business app, a WhatsApp product, and
use its phone number id and a permanent access token). A WhatsApp send failure is logged and never
breaks the request that triggered it — the in-app notification is always there regardless.

Real-world limitation worth knowing (not something to configure around): Meta only allows free-form
WhatsApp text outside a pre-approved template within 24 hours of the customer last messaging the
business number. For notifications sent to someone who never started a WhatsApp conversation with your
number, set up an approved message template in the Meta Business dashboard for production use.

Notification e-mails use Laravel's Markdown mail component with an RTL layout
(`resources/views/vendor/mail`, published and patched for this project — do not re-run
`vendor:publish --tag=laravel-mail` without re-applying the `dir="rtl"` / brand-color changes).

## 4. Nginx + PHP-FPM

```nginx
server {
    listen 443 ssl http2;
    server_name your-domain.com;
    root /var/www/shams/public;
    index index.php;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    charset utf-8;

    # Listing photos: up to 8 files x 5 MB. Keep this above 8 * max_image_kb plus form overhead.
    client_max_body_size 50M;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        fastcgi_hide_header X-Powered-By;
    }

    # Built assets are fingerprinted: cache them for a year.
    location /build/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # Uploaded images (storage:link) are immutable too, their names are random.
    location /storage/ {
        expires 30d;
        add_header Cache-Control "public";
        access_log off;
    }

    location ~ /\.(?!well-known).* { deny all; }
}

server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}
```

PHP (`/etc/php/8.3/fpm/php.ini`) must allow the same uploads and enough memory for GD:

```ini
upload_max_filesize = 8M     ; per image: config('classifieds.max_image_kb') is 5120 KB
post_max_size       = 50M    ; 8 images + form fields
max_file_uploads    = 20
memory_limit        = 256M   ; GD decodes images to raw pixels (a 6000x4000 photo needs ~100 MB)
max_execution_time  = 60
opcache.enable      = 1
```

Reload after changing: `sudo systemctl reload php8.3-fpm nginx`.

## 5. Queue worker (Supervisor)

Image conversions (thumb/medium/large WebP) run on the queue, so a worker must always be running.

`/etc/supervisor/conf.d/shams-worker.conf`:

```ini
[program:shams-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/shams/artisan queue:work --sleep=3 --tries=3 --max-time=3600
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=2
redirect_stderr=true
stdout_logfile=/var/www/shams/storage/logs/worker.log
stopwaitsecs=3600
```

```bash
sudo supervisorctl reread && sudo supervisorctl update && sudo supervisorctl start shams-worker:*
```

Until a conversion exists the site serves the original image, so a stopped worker degrades
performance but never breaks pages.

## 6. Scheduler (cron)

One cron line runs every scheduled task (`crontab -u www-data -e`):

```cron
* * * * * cd /var/www/shams && php artisan schedule:run >> /dev/null 2>&1
```

What it runs (see `routes/console.php`):

| Task | When | What |
|---|---|---|
| `listings:expire` | daily | flags active listings past their expiry date as expired |
| `listings:remind-expiring` | daily | notifies owners 3 days before expiry |
| `searches:notify` | daily | notifies users of new listings matching their saved searches |
| `listings:purge` | weekly | permanently deletes listings expired for 90+ days, with their images |
| `sitemap:generate` | daily | rewrites `public/sitemap.xml` and the `Sitemap:` line of `robots.txt` |
| `backup:clean` / `backup:run` / `backup:monitor` | 01:30 / 02:00 / 03:00 | backups (below) |

Run `php artisan sitemap:generate` once after the first deploy so `robots.txt` gets the real domain.

## 7. Deploy script (updates)

```bash
#!/usr/bin/env bash
set -euo pipefail
cd /var/www/shams

php artisan down --retry=60          # maintenance mode (503 page)
git pull --ff-only
composer install --no-dev -o
npm ci && npm run build
php artisan migrate --force
php artisan storage:link 2>/dev/null || true
php artisan optimize                 # config, route, event and view caches
php artisan queue:restart            # workers reload the new code
php artisan up
```

Roll back with `git checkout <previous tag>` and the same steps; migrations are small and
reversible (`php artisan migrate:rollback --step=N`).

After changing `.env` run `php artisan config:clear && php artisan optimize`.

## 8. Backups (spatie/laravel-backup)

`config/backup.php` is set up for a **daily database dump + uploaded images** (`storage/app/public`;
generated conversions are excluded because `php artisan media-library:regenerate` rebuilds them).
Archives go to `storage/app/private/<APP_NAME>/` by default; point `BACKUP_DISK` at an S3/off-server
disk for real safety. Old backups are pruned by `backup:clean`; failures email `BACKUP_NOTIFICATION_EMAIL`.

Run one by hand: `php artisan backup:run` and list them with `php artisan backup:list`.

### Restore test (do this before you need it)

A backup you have never restored is not a backup. Quarterly, on a scratch machine:

1. Copy the newest zip from the backup disk and unzip it.
2. Create an empty database and import the dump:
   `gunzip < db-dumps/mysql-shams.sql.gz | mysql -u root -p shams_restore`
3. Copy the extracted `storage/app/public` folder into a fresh checkout's `storage/app/public`.
4. Point `.env` at `shams_restore`, run `php artisan storage:link`, open the site and check that
   listings, images and the admin login work.

This exact procedure was run once against a local dump (`backup:run` with `DB_DUMP_BINARY_PATH`
pointed at WAMP's `mysqldump`, then restored into a scratch `shams_restore_test` database): every
table's row count matched the source, `php artisan tinker` against the restored database returned the
same listings and a FULLTEXT search worked, and `launch:check` ran cleanly against it. Repeat it
against your actual production backup disk before relying on it.

## 9. Security checklist

- HTTPS everywhere; `SESSION_SECURE_COOKIE=true` (the app also sends HSTS on secure requests).
- `APP_DEBUG=false`, and never commit `.env`.
- Change `ADMIN_PASSWORD` after the first login, and give staff the `moderator` role instead of `admin`.
- The app sends `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy` and `Permissions-Policy`
  headers. No CSP is sent because Alpine.js needs `unsafe-eval` (see `App\Http\Middleware\SecurityHeaders`).
- Rate limits protect OTP sending/checking, login, ad creation, phone reveal, reports, messages and
  reviews, on both the website and the API (`api/v1/*` reuses the same named limiters).
- Keep PHP, MySQL and Composer dependencies updated (`composer audit`).
- API tokens (`personal_access_tokens`, Laravel Sanctum) do not expire by default
  (`config/sanctum.php` → `expiration`, in minutes). Leave them non-expiring for a "stay logged in"
  mobile app, or set an expiration and have the client re-authenticate; either way, a banned user's
  token stops working on their very next authenticated request regardless
  (`App\Http\Middleware\Api\EnsureApiUserIsNotBanned`), and `POST /api/v1/auth/logout` revokes the
  current one immediately.

## 9a. Public API (`/api/v1`)

The full contract is [`docs/openapi.yaml`](openapi.yaml) — open it in any OpenAPI viewer (e.g.
[Redoc](https://redocly.github.io/redoc/) or Swagger UI), or serve it directly (see below). Nothing
extra needs installing or configuring for it beyond a normal deploy: it shares the database, queue,
mail/SMS/WhatsApp drivers and rate limiters with the website, and `php artisan migrate` already
created its `personal_access_tokens` table (Laravel Sanctum, installed via `install:api`).

To publish the spec itself as a page on the site (optional — nothing depends on this), add a route
that returns `docs/openapi.yaml` with `Content-Type: application/yaml`, or copy it into `public/` and
point a Swagger UI/Redoc HTML page at it.

**No native mobile app ships in this repository.** Building one (Swift/Kotlin or a
React Native/Flutter client) needs a real device/simulator build toolchain, code signing and app store
accounts — none of which can be set up or tested in this environment. The API above is the complete,
tested surface such an app would be built against (`tests/Feature/Api`); the PWA below is what stands
in for an installable app in the meantime.

## 9b. PWA (installable site, offline support)

`public/manifest.json` and `public/sw.js` are plain static files — a real webserver (or
`php artisan serve`'s dev router) serves them directly, nothing to configure. Two things to keep in
mind:

- **HTTPS is required.** Browsers only register a service worker over `https://` (or `localhost` in
  development). If `public/sw.js` fails to register in production, check `APP_URL` and the certificate
  first.
- **Icons**: `public/icons/*.png` are simple generated placeholders (a sun on the brand color). Replace
  them with real app icons (192×192, 512×512, and a 180×180 `apple-touch-icon.png`) before a real
  launch, and bump `CACHE_VERSION` in `public/sw.js` if you ever change its caching logic — that is
  what forces every visitor's browser to drop its old cache on the next visit.

## 9c. Search engine: MySQL FULLTEXT (default) or Meilisearch (optional)

The plan calls for MySQL only, and that is what runs with a stock `.env`: `ListingSearch` matches
against an InnoDB FULLTEXT index (`listings.search_text`), Arabic-clitic-aware (see
`app/Services/ArabicText.php`), with LIKE as a fallback for words too short for FULLTEXT. No extra
service, nothing to install, nothing to run — this is what every other test in the suite and CI
exercise, and it is what a deploy gets unless you opt into the below.

**Meilisearch** is an optional drop-in via [Laravel Scout](https://laravel.com/docs/scout) for
sites that want typo-tolerant search (`app/Models/Listing.php` already has the `Searchable` trait
and a minimal `toSearchableArray()` — just `id` and the same normalized `search_text` the FULLTEXT
index uses). It changes nothing else: category, price, dynamic-field and visibility filtering
(`scopeVisible()`, banned owners, expired/pending listings) all still run as ordinary SQL `WHERE`
clauses against whatever ids Meilisearch returns — Meilisearch only ever narrows the candidate set,
it never bypasses a filter the FULLTEXT path would have enforced.

To turn it on:

```bash
# 1. Run a Meilisearch server (Docker, a systemd service, or Meilisearch Cloud) and note its URL/key.
# 2. In .env:
SCOUT_DRIVER=meilisearch
MEILISEARCH_HOST=http://127.0.0.1:7700
MEILISEARCH_KEY=<your master or API key>

# 3. Create the index with the right settings, then backfill it from the database:
php artisan scout:sync-index-settings
php artisan scout:import "App\Models\Listing"
```

From then on, listings stay in sync automatically (created/updated/deleted, synchronously by
default — set `SCOUT_QUEUE=true` in `.env` plus a running queue worker to move that off the request
cycle on a busy site). To go back to FULLTEXT, just remove/unset `SCOUT_DRIVER` — nothing else to
undo.

`tests/Search/MeilisearchSearchTest.php` verifies this path (typo tolerance, and that every SQL
filter still applies on top of Meilisearch's candidates) but skips itself unless a real Meilisearch
server is reachable, so it never affects a normal `php artisan test` run or CI:

```bash
SCOUT_DRIVER=meilisearch MEILISEARCH_HOST=http://127.0.0.1:7700 MEILISEARCH_KEY=... \
  php artisan test --filter=MeilisearchSearchTest
```

## 10. Content to review before launch

- **Static pages** (`/admin` → الصفحات الثابتة): review the terms and privacy policy with a lawyer.
  The contact page reads its e-mail from `CLASSIFIEDS_CONTACT_EMAIL` the first time it is seeded only;
  edit the page directly in the admin panel afterwards to change it.
- **Blocked words**: `config/classifieds.php` → `blocked_words` ships a default Arabic list (drugs,
  weapons, common scam phrases) matched after Arabic normalization; extend it with
  `CLASSIFIEDS_BLOCKED_WORDS="word one,word two"` in `.env` instead of editing the file.
- **Phone defaults** for another country: `CLASSIFIEDS_PHONE_COUNTRY_CODE`, `CLASSIFIEDS_CURRENCY_LABEL`,
  `CLASSIFIEDS_CURRENCY_CODE`, and the national number lengths in `config/classifieds.php`.

## 10a. Pre-launch check

```bash
php artisan launch:check           # human-readable table; exit code 1 on any failure
php artisan launch:check --strict  # also fail on warnings (recommended in CI/a release script)
php artisan launch:check --json    # for scripting
```

It checks: `APP_ENV`/`APP_DEBUG`/`APP_URL` (HTTPS), secure session cookies, the queue and cache
drivers, the SMS provider and its credentials, the mail transport, CAPTCHA, blocked words, the contact
e-mail/page, that the admin password was changed, the database engine and pending migrations, PHP
extensions (including GD WebP support), upload/memory limits, the `public/storage` link, the sitemap,
and whether `mysqldump` is available for backups. Run it after every `.env` change and before every
release.

## 10b. Continuous integration

`.github/workflows/tests.yml` runs on every push/PR: Pint (formatting), the Pest suite against a MySQL
8 service container, and `npm run build`. It does not run the Playwright suite (`npm run e2e`), which
needs a full PHP/MySQL toolchain and a real browser and is meant to be run before a release, not on
every commit.

## 11. Optional: error monitoring (Sentry)

Not installed by default. To add it:

```bash
composer require sentry/sentry-laravel
php artisan sentry:publish --dsn=https://<key>@o0.ingest.sentry.io/<project>
```

then set `SENTRY_LARAVEL_DSN` in `.env` and add `Sentry\Laravel\Integration::handles($exceptions);`
inside `withExceptions()` in `bootstrap/app.php`.

## 12. Health check

`GET /up` returns 200 when the application boots; point your uptime monitor at it.
